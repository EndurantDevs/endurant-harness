# Compact Engineering Checkpoint

Use for a replan, high-risk work, large-output boundary, or session continuation. Keep it in task memory or an untracked temporary file unless the repository requests otherwise.

```text
Phase: scan | change | prove | handoff | blocked
Task scale: local | medium | high-risk
Write gate: open | closed — evidence missing
Done gate: open | closed — proof missing

Goal / decisive proof:
Constraints / non-goals:
Baseline: exact command and decisive signal
Execution path: entry -> calls/state -> divergence
Hypothesis/design: claim and evidence
Disproving check:
Credible alternatives:
Predicted surface:
Pre-existing user changes:
Actual changes:

Passed:
- exact command — decisive result

Failed:
- exact command — class and signal

Blocked / not run:
- exact command — reason and residual risk

Replan attempts: terminal failure; class; agent role
Candidates (max 3): strategy; predicted signal; stop/recovery; model/effort
Accepted/rejected: candidate; same-oracle evidence
Next packet:
```

Refresh after a major discovery, edit, replan, large output, or phase boundary. Remove stale hypotheses. On resume, compare it with current instructions, `git status`, and diff before trusting it. Never open the done gate while required verification is missing.
